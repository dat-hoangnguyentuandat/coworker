Multi-tunnel

Mỗi tài khoản ChatGPT cần một Secure MCP Tunnel riêng — vì tunnel gắn với tổ chức OpenAI của từng tài khoản. Coworker chạy nhiều tunnel song song, tất cả nối về cùng MCP server trong máy bạn.

Vì sao mỗi tài khoản cần một tunnel?

Tunnel tạo trên OpenAI Platform thuộc về tổ chức của tài khoản tạo nó. Tài khoản A không thấy tunnel của tài khoản B. Vì vậy khi chạy multi-account, bạn cần một tunnel + một Runtime API key cho mỗi tài khoản, và trong mỗi tài khoản ChatGPT tạo app "Coworker" từ Cài đặt → Plugin → trang quản lý plugin → + → Ứng dụng mới, trỏ tới tunnel tương ứng.

Thêm tunnel cho từng tài khoản

  1. Mở mục Kết nối

    Coworker → Kết nối → Secure MCP Tunnel. Danh sách tunnel hiển thị tên, trạng thái, Tunnel ID và nút xóa cho từng dòng.

  2. Lấy tunnel của tài khoản thứ hai

    Đăng nhập ChatGPT bằng tài khoản 2, vào platform.openai.com/settings/organization/tunnels → Create tunnel + tạo Runtime API key.

  3. Nhập vào app

    Ở form dưới danh sách: điền Tên tài khoản, Tunnel ID và Runtime API key → Lưu. Tunnel mới sẽ xuất hiện trong danh sách.

  4. Lặp lại cho từng tài khoản

    Mỗi tài khoản thêm một dòng. Bật MCP là toàn bộ tunnel đang bật cùng khởi động, mỗi tunnel một process tunnel-client riêng.

Đọc trạng thái tunnel

Trạng tháiÝ nghĩa
Đang chạyTunnel-client đã kết nối, ChatGPT của tài khoản đó gọi được tool.
Đang khởi độngProcess tunnel-client đang dựng kết nối (vài giây).
Đã dừngTunnel hợp lệ nhưng MCP đang tắt.
Đã tắtTunnel chưa bật trong cấu hình.
LỗiKey sai, tunnel bị xóa trên Platform, hoặc mạng không nối được — hover log để xem chi tiết.

Dòng trạng thái tổng hiển thị dạng 2/3 đang chạy; log MCP gộp chung mọi tunnel, gắn tiền tố tunnel để phân biệt.

Sửa và xóa

  • Đổi nhãn / cập nhật key: nhập lại Tunnel ID cũ ở form, điền tên hoặc key mới → Lưu. Để trống Runtime API key = giữ key đã lưu.
  • Xóa tunnel: nút xóa cuối dòng. Chỉ xóa cấu hình trong app — tunnel trên OpenAI Platform vẫn còn, dùng lại được.
Không dùng một key cho hai tunnel

App từ chối lưu — key gắn chặt tunnel, dùng lại key sẽ khiến tunnel-client đầu tiên mất phiên.
